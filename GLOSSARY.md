# Glossary

One entry per term: what it is, and its boundary. Vocabulary here is used as-is in code, docs and PRs. Record a new term in the same PR that introduces it.

| Term | Code name | What it is |
|---|---|---|
| **Gateway** | `intent-gateway` | The self-hosted gateway a developer runs with npx or Docker. It talks to the agent over MCP and to Intent Cloud for offers and carts. |
| **Intent Cloud** | — | The hosted service behind the gateway: product discovery, merchants, offers and carts. Reached only through its public API host. |
| **Gateway policy** | `policy.yaml` | The developer's YAML rules for what may leave the gateway and how much may be spent. It can only narrow Intent Cloud's rules, never loosen them. |
| **Cloud baseline** | `CLOUD_BASELINE` | The rules Intent Cloud enforces, held by the gateway as the loosest policy it will run: passkey approval, at most 3 items, US delivery, the excluded categories. Every policy is checked against it. |
| **Policy library** | `intent policy add` | The public, signed collection of shared gateway policies, reviewed by PR. |
| **Policy lock** | `policy.lock` | The file beside `policy.yaml` that `intent policy add` writes: the library policy's name, the commit it came from, its sha256, its source (`bundled` with the gateway, or `github` for `--commit`) and `policy_sha256`, the hash of the `policy.yaml` it wrote. It records what was applied, not the policy itself; a lock whose `policy_sha256` does not match `policy.yaml` is stale. |
| **Shopping session** | session key | A short-lived key for one anonymous run of searches and carts. The gateway sends no identifier that links it to other sessions. Not an account. |
| **Session keyid** | `gw-…`, `src/signing` | The shopping session's identity on the wire: `gw-` plus the base64url of its raw Ed25519 public key. Self-certifying: Intent Cloud reads the public key from it, with no registration. Every request carries it in its RFC 9421 signature (contract appendix C). |
| **Disclosure log** | — | The gateway's local hash chain of every field it sent to Intent Cloud, appended before each send. |
| **Disclosure receipt** | — | Intent Cloud's signed statement of what it received, matched against the disclosure log. |
| **Disclosed cloud** | `createDisclosedCloud`, `connectCloud` | The only way gateway code reaches Intent Cloud: each call's outbound body is checked for buyer identity, logged with its exact bytes and headers, then sent, and what came back is logged. |
| **Unacknowledged send** | `unacknowledged` | A logged send with no HTTP response, or a non-2xx response with neither `Intent-Contract-Version` nor a receipt. `intent verify` reports it and does not fail (ADR-0006). |
| **Discarded response** | `discarded` | A response that should have carried a valid receipt and did not: a 2xx (whose content the gateway never uses), any response with `Intent-Contract-Version`, or any invalid receipt. `intent verify` fails on it (ADR-0006). |
| **Local audit trail** | — | The same local hash chain read as a whole: disclosure log entries plus each signed Approval the gateway verified. |
| **Fenced lease** | `audit.lock` | The expiring lock a writer of the local hash chain holds while it appends. Before each write the writer checks it still holds the lease and that the chain's tail has not moved; if either fails, that writer is refused for good. Liveness comes only from the expiry, never from a process id. |
| **Approval** | — | A buyer's passkey signature over one purchase snapshot, returned signed by Intent Cloud, verified by the gateway and appended to the local audit trail. One per purchase. |
| **Approver pin** | `approver_pin` | The passkey credential the gateway trusts for Approvals: the first one it verified, or one accepted later with `intent approver accept` at a terminal. Any other credential is flagged (ADR-0011). |
| **Approver fingerprint** | `approverFingerprint` | How a person compares passkeys: the SHA-256 of the canonical JSON of the passkey's public key (JWK), as 16 groups of 4 hex characters. The `approver_pin` and `approver_flag` entries carry it, the panel and stderr show it, and `intent approver accept` asks for it. |
| **Key statement** | `verifyStatement` | Intent Cloud's statement, signed by an offline root key pinned per host, listing its current and next receipt and approval keys. Valid 90 to 180 days (ADR-0006). |
| **Fake Cloud** | `startFakeCloud`, `src/cloud-fake` | A stand-in for Intent Cloud on 127.0.0.1 that follows the public contract and signs with its published test keys (vectors s1, d1, e1). Only tests and demo mode use it; it ships in the package for demo mode only. |
| **Soft passkey** | `SoftPasskey` | A passkey held in memory (ES256 or RS256) that answers the confirm page's WebAuthn request in tests and on the demo confirm page, in place of the buyer's authenticator. |
| **Demo mode** | `intent demo`, `startDemo`, `src/demo` | The gateway against the Fake Cloud in-process, with the sample catalog and the published test keys, so a developer can try the whole flow with no setup. Its chain lives in `<data>/demo`, starts with a `session` entry `{mode: "demo"}` and never mixes with a real one. Every tool result carries "DEMO: test keys, sample catalog, nothing can be bought." |
| **Test root key** | `TEST_ROOT_KEY` | The `cloud-root-1` key of vector s1, whose private seed is public. Demo mode trusts only it; no Intent Cloud host may ever pin it. |
| **Demo confirm page** | `startConfirmPage` | The local page at `http://127.0.0.1:<port>/confirm/c/<link>` that shows a demo purchase snapshot with "Approve with demo passkey" and "Reject". A click signs with the demo's soft passkey, kept per demo data dir. It is a local stand-in for the passkey step: any program that can reach 127.0.0.1 can press it. |
| **Demo code** | `Demo.code`, `<data>/demo/approval-code` | Six digits, new on every demo start, that Approve on the demo confirm page needs. Printed on the gateway's stderr and kept in a 0600 file, never in a tool result, so an agent that reads only tool results cannot approve. A speed bump, not proof of a person. |
| **Invocation** | `INTENT`, `invocation()` | The command that runs this gateway, printed before every command the gateway suggests: `npx -y <spec>`, `node /abs/dist/main.js`, `intent`, or `docker exec <container> intent`. |
| **Readiness check** | `MissingDetail` | Before a search, the gateway checks it has a product or category, a budget and a 5-digit US ZIP. It lists the missing ones for the agent to ask the user about, never guesses one, and sends nothing until all are there. |
| **Spend history** | `spendHistory` | The purchases the policy's daily and weekly caps count, read from the local hash chain: every verified approval, plus every approval still pending and unexpired, so carts opened in parallel cannot add up past a cap. |
| **Disclosure summary** | `Sent: … / Blocked: …` | The last line of every tool result: the field names each request sent to Intent Cloud and whether a verified receipt acknowledged it, then what was held back. Names only, never values. |
| **Buyer identity** | `findIdentity` | Anything that identifies or pays as the buyer: name, postal address, card number, email, phone. The gateway refuses to send it; a ZIP code alone is not buyer identity. |
| **Hand-off** | `continue_url` | The step where the buyer leaves our confirm page for the merchant's checkout and pays there. The gateway never sees the buyer's name, address or payment. |
| **Verify command** | `intent verify` | Checks the local hash chain, matches receipts to the log, re-verifies approvals, and self-checks the npm package or image. |
| **Doctor** | `intent doctor` | Checks the setup one line at a time (data dir, active policy and lock, chain and lease, root key, Intent Cloud's contract and key statement) and names the fix for each problem. Its requests go through the disclosure log. |
| **Default policy** | `DEFAULT_POLICY` | The bundled library policy the gateway runs when no `policy.yaml` exists, in every mode: `zip-only`, so the only buyer detail a search sends is a 5-digit ZIP. `strict-default` (no ship-to, so no search) stays available through `intent policy add strict-default`. Every command that uses the default says so. |
| **Canonical JSON** | `jcs` | RFC 8785 JSON restricted to safe integers (no fractions, no NaN, no lone surrogates): the exact bytes the gateway hashes and verifies signatures over. |
| **Data directory** | `Config.dataDir` | Where the gateway keeps its state: `INTENT_DATA_DIR`, else `/data` in the image, else the platform's per-user data folder. Resolved only by `src/config`. |
| **Root key pin** | `PINNED_HOSTS` | The root public key (kid `cloud-root-1`) the gateway trusts for one Intent Cloud host. It holds only that key; everything else trusted comes from the statement the key signs. `--trust-keys` replaces it for an unpinned host. |
| **Self-check** | `label: "self-check"` | A provenance or signature check of the gateway's own npm package or image, run by the installed gateway code itself. A tampered install could tamper with it too, so it always names the outside checks (`npm audit signatures`, `cosign verify`) that settle the question. On a build that was never published (no `build-info.json`, or the registry has no such name@version) it reports "not run" and does not fail `intent verify`; `--skip-install-check` skips it offline and says so. |
| **Release identity** | `releaseIdentity(version)` | The Sigstore certificate identity of a release: `https://github.com/golden007eye/intent-gateway/.github/workflows/release.yml@refs/tags/v<version>`, issued by GitHub's OIDC provider. npm provenance, the image signature and the SBOM attestation must all carry it (`docs/release.md`). |
| **Panel** | `startPanel` | The read-only local web page on `127.0.0.1`: chain status, disclosures, pending approvals, the approver pin fingerprint and flags. GET only; it never writes the chain and loads nothing from outside the gateway. |
| **Public contract** | `contract/` | The Intent Cloud public contract: the gateway API spec, its normative appendices and test vectors, published under Apache-2.0. The gateway vendors it byte for byte; `contract/SOURCE.md` names the version and the sha256 of `SHA256SUMS`. |
| **Test vector** | `contract/vectors/*.json` | An input with the exact output Intent Cloud computed for it. Both sides must reproduce it byte for byte; formats are shared this way, never by sharing code. |
| **Claims rule** | `scripts/claims.test.ts`, `docs/claims-allow.txt` | Invariant 5 as a test: every sentence in the README, the docs and the CLI's strings that names Intent Cloud as an actor uses a verb from a short, checkable list (receives, acknowledges, returns, signs, enforces, reported), or is allow-listed with a reason. |
| **Feature map** | `docs/feature-map.json` | The features the docs describe as working, each with the `intent` subcommand or test file that proves it. A `!!! planned` block names its feature in a `<!-- feature: <id> -->` line, and that id must not be in the map. |
